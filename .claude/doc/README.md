# Decision records

Long-form reasoning behind decisions that the code cannot explain on its own — why a framework
was chosen, why a convention exists, what alternatives were rejected and on what evidence.

**What belongs here:** a decision that outlives the conversation that produced it, that a future
contributor (or session) would otherwise re-litigate from scratch.

**What does not:** how-to guidance (that is a skill in `../skills/`), API contracts (`mock-api-contract`),
task tracking (`TODO.md`), or notes that stop being true once a PR merges. If a document would be
deleted after the work lands, it is a scratch note, not a decision record.

Each document states its status up front — in flight or settled — and is updated when the work it
describes completes, so a stale plan never reads as current fact.
